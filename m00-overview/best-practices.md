# Best Practices

Regeln für den Umgang mit dem NC/CAPA-Agenten, über alle Module hinweg.

| Regel | Grund |
| --- | --- |
| Rolle, SOP und Fall mitgeben | Ohne Kontext antwortet das Modell mit Wahrscheinlichem, das klingt sicher und kann erfunden sein |
| Jede Aussage gegen die Quelle prüfen | Nur belegte Sätze sind auditfest; die fünf Prüfpunkte machen das wiederholbar |
| Fakten, Annahmen und offene Punkte trennen | Lücken und Widersprüche sind Information für den NC-Eigner, keine Fehler, die geglättet werden dürfen |
| Keine Ursache in der Problembeschreibung | Die SOP verlangt eine lösungsneutrale Beschreibung; Ursachen sind Ergebnis der Analyse |
| Isolation und Containment von der Korrektur trennen | Sperren begrenzt den Schaden, die Korrektur folgt erst nach Umfang und Risikobewertung |
| Der Agent schlägt vor, das Team entscheidet | Kundenvorgabe: methodische Unterstützung, keine Ursachenfindung und keine Freigabeentscheidung durch die KI |
| Daten aus ERP und CAQ-System bringt das Team mit | Der Agent hat keinen Systemzugriff und darf nichts ergänzen |
| Zuerst das Problem, dann der Agent | Der Use-Case-Canvas zeigt, wo der Hebel liegt; sonst entsteht ein Agent für das falsche Problem |
| Höchstens sechs Skills, entlang der SOP-Schritte | Wenige, klar abgegrenzte Skills lassen sich testen und pflegen |
| Jeder Skill nennt seine Grenzen | Der Agent erkennt, was beim Menschen bleibt |
| Nur Part 1 an den Agenten, Referenz erst danach | Der Vergleich bleibt fair |
| Eine Änderung je Tuning-Schritt, Version hochzählen | Wirkung lässt sich zuordnen, Änderung in einer Zeile dokumentieren |
| Fehler bei einer Aufgabe: Skill ändern, bei allen Antworten: Anweisungen | Längere Prompts sind kein Tuning |
| Agenten nach SOP-Änderungen neu testen | Skills und Testfälle veralten sonst unbemerkt |
| KI-Unterstützung im NC-Vorgang dokumentieren | Nachvollziehbarkeit gegenüber Audits |
| Keine Patientendaten und keine personenbezogenen Daten | Datenschutz; Übungsfälle sind anonymisiert |
